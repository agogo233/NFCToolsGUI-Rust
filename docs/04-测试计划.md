3. `NFCToolsGUI/test/ui/main.js:17` 唯一**完整合法**的扇区 0

   该文件其余样本行长度只有 30 / 28 字符，是 UI 布局占位串，**不可**作为 fixture。

`default_1k.mfd` / `sector_pattern.mfd` 两个样本 dump **尚未建**：dump 单测目前用
`(0..n).map(|i| …)` 合成字节，覆盖往返与校验；真实样本待 S5/S6 拿到卡后补。

## 3. 单元测试用例清单（按模块）

### model/hex
- 字节↔hex 互转；小写/大写输出；非法字符拒绝；空输入；奇数长度拒绝

### model/dump
- 1024B → 64 **块** → **16 扇区**（每扇区 4 块 × 16B）；非 64 倍数拒绝；空文件拒绝
- `to_sector_lines`/`from_sector_lines` 往返一致（含 4096B = 64 扇区的非 1K 尺寸，
  验证扇区数不硬编码为 16；注意真实 M1 4K 是 40 扇区，64 只是任意尺寸）
- 非法输入分两层：`to_sector_lines`/`from_sector_lines` 拒空与非 64 倍数；
  `validate` 拒行数≠4 / 行长≠32 / 非 hex（仅 `check_content=true` 时查字符集）
- `from_sector_lines` 自查行长，不依赖调用方记得先调 `validate`
- `split_trailer` 尾块四段（0,12)/(12,18)/(18,20)/(20)；`block0_hex` 大写 32；`uid_hex` 14

### model/keys
- save_keys：合并去重、剔除 13 默认、空文件初始化、返回新增、已有相同 key 不重复

### model/parse
- **全部 fixture 驱动断言**：
  - keyInfoStatistic：F 已知（key=16..28、type=13、sector=i/2）、U 未知、混合
  - UID：`UID (NFCID1):` 14 字符去空白
  - ETA：`[Key: ` 计数、节流、100% 收敛
  - libnfc-collect：uid 8 字符、`(sector N)`、类型字符
  - cropto1_bs / nfc-mfdict：`Key found:`/`Found Key: ` 12 hex
  - nfc-list：opened/unable/空输出 三判定（原版无 `No NFC device found` 串，勿臆造）
  - `\33[2K` 剥离

### dialogs
- `MockDialog` 预设结果按序返回；结果用尽 → 视作取消
- `MockDialog` 逐字记录请求（title / defaultPath / filters）供断言
- `dump_filter` 扩展名为 `["dump", "mfd"]`

### tasks/mfoc
- ETA 基线：13+keys.txt 条数+-k 条数
- percent 递增不降、上限 100
- 节流 1s（1s 内多次调用只推一次）
- **首帧必被节流**（原版 bug #15 的回归锁）
- 无换行时只缓冲不产出；残行跨 chunk 续接
- 达到分母 → 推 100 + 回落纯状态文案 + 之后不再产出
- 越界（单帧计数超分母）仍收敛
- **分母为 0 不除零**（直接走收敛分支）
- format_duration 边界：0→`00:00`、59→`00:59`、3599→`59:59`、3600→`01:00:00`；再验 1/60/61/3661/86399/86400
- `count_keys_done`：`[Key: ` 带空格才计；`[Key:` 不计
- `arg_keys` 只认 `-k` 前缀；非 `-k` 参数不计入分母
- `mfoc_args` 前置 `-O<temp>` + `-f<keys>`
- `apply_eta` 写状态条与进度；空更新不改动
- 保存：取消→自动存 dumpfiles 默认名（uid 前缀；无 uid → `card_`）；temp 空→删文件+提示且**不弹框**；用户选路径→`DumpSaved` + `dump_history`；rename 失败→`Failed{failed:true}` 且 temp 保留；`dumpfiles/` 缺失→自动创建

### tasks/detect
- `detect_args`：落盘模式 `-O<temp>` + `-f`；只探测模式 `-N` + `-f`（同一 `-f`）
- `after_detect`：无 unknown → `Proceed`；有 unknown → `NeedGuidance{count}` 且状态留有引导文案
- 落盘模式 temp 缺失 → 报「读卡失败」；0 字节 → 删除 + 报「未读到卡内容」；有效 → `Proceed` 且不删
- 只探测模式忽略 temp 是否存在
- 引导文案含数量，两个按钮 action 名为 `hard-nested` / `dict-test`
- `check_key_file_exists`：缺失则建（含父目录），已存在不覆盖
- `purge_empty_temp`：只删 0 字节

### dialogs（S6 补：危险确认）
- `confirm_danger` 默认实现返回 `false`（安全默认：未接真实实现者时拒绝写卡）
- 只实现 save/open 的旧实现者也继承该默认
- `MockDialog` 确认框按序返回；用尽后返回 `false`（拒绝）
- 确认请求逐字记录（title / message）

### tasks/card_write
- `mfclassic_write_args` 6 段逐字断言；`mfclassic_format_args` 源与 temp 同路径
- `mfsetuid_args` / `mflock_args` 精确断言
- `resolve_dump_id` 绝对 / 相对 / 带子目录
- `read_block0_hex` 大写、取前 16 字节；短文件截短但 `block0_is_valid` 判无效
- `block0_is_valid` 拒 0/4/31/33 长
- 写 UID 确认框正文拼上 block0；锁卡确认框含「不可恢复」
- `prepare_write` 三分支：确认 / 确认框取消 / 文件框取消（后者不再弹确认框）
- `prepare_write_uid`：过短与读失败**都不弹确认框**；成功才弹
- **安全锁**：未预设确认结果时写卡与锁卡一律 `Cancelled`
- `report_write_result`：`Some(0)` 成功、其余（含 `None` 即被 kill）均失败

### tasks/hard_nested
- 采集 7 参逐字断言；扇区→块换算（0→3、1→7、15→63、39→159）
- `nonces_default_name` 三者齐全才拼 `{uid}_{sector}{type}`，缺任一回落 `nonces`
- **状态机转换矩阵**：begin(autoRun)→Detect、begin(manual)→Collect、
  after_detect 三分支（无 known / unknown 空 / 正常采集）、
  after_collect 按 collect_only 分裂 SaveNonces / Crack、after_crack 按 autoRun 分裂
- **autoRun 终止回归**：不用测试内短路，终止判定必须真的走 `after_detect`；
  2 轮破解 + 3 次 Detect = 7 次迭代
- **autoRun 无进展兜底**：`after_crack_guarded` 在数量未减少时停
- `cancel` 可达 `StopCancelled`
- `after_detect` 记下队首 unknown 为 target
- 进度：`3/3`→1/3、`1/3`→3/3、`0/3`→4/3；percent 上限 100；total=0 返回 None
- `pop_matching_unknown`：只移队首；非队首命中与类型不符均不移；空队列不 panic
- 文案含进度时必含 `HardNested`；no-known-key 断言「未**发现**已知密钥」
- `clear_nonces` 建目录 + 截断；`nonces_is_empty` 文件不存在视作空

### tasks/dict_test
- `dict_args` 四参逐字；含起始位置；路径含空格时整串传递
- `dict_file_name` 跨 `/` 与 `\` 切分；末尾分隔符返回空串
- `default_config` 有 / 无 unknown 两态
- `apply_dict_choice` 更新 `dict_path`；取消时保持旧值
- `report_found_key` 落盘非默认密钥；**默认密钥命中不落盘也不推事件**

### data/registry
- JSON 读写往返；字段校验；新卡自动追加；文件不存在初始化
- 仅 `uid` 的部分 JSON 可解析（其余字段走 serde default）
- 同 UID 重复追加被拒（返回 false 且不覆写）
- 原子写后不留 `.tmp` 残留；父目录自动创建
- 畸形 JSON → `RegistryError::Parse`

### paths / i18n
- 默认路径；时间戳 `yyyy_MM_dd_HH_mm_ss`；dump 默认文件名
- zh-CN 150 key 全覆盖（含 4 个原版拼写错误 key 名）；未知 key 回退为 key 本身（「仅中文」决策：无语言选择/回退分支）

### command
- **30 action 注册完整性**（防漏项）；每个 action 前置门禁映射正确

### runner
- 门禁矩阵：未连接+nfc-list 例外放行；未连接+其他→NotConnected；运行中→Busy
- 退出码：0→Ok、非0→Failed(code)、kill→Killed
- MockToolRunner 逐行回调顺序

### serial
- `is_device_list_equal` 长度/顺序矩阵（对标 renderer `isListEqual`，顺序敏感）
- `PortScanner`：首次 `Some`、重复 `None`、拔空→`Some([])`、换序→`Some`、枚举错误透传
- `judge_connect`：opened / unable / 空输出 三判定；标记跨块拼接可命中；双标记以成功优先
- `write_nfc_config`：内容逐字断言；父目录缺失→`DeviceError::WriteConfig`
- `ConnectFlow::begin`：写 conf 后 start；写失败 / 门禁拒绝 → `Failed` 且未 start
- `ConnectFlow::finish`：先 `DeviceState` 后 `TaskDone`；未命中任何标记 → `Some(false)`
- `disconnect`：清 `current_device` 并置 `DeviceState::None`

## 5. `--selftest` 模式（nfc-core/src/bin/selftest.rs）

启动参数 `--selftest`，用 **MockToolRunner + 内置样本 dump + 脚本化 DialogProvider** 依次跑通：
1. scan → connect（mock 成功）→ detect → guidance
2. read-IC → dump 自动保存 → guidance
3. write-IC（确认接受）→ 校验命令
4. format-card
5. write-uid / lock（确认接受）
6. hard_nested 手动全链
7. hard_nested autoRun 递归
8. dict_test
9. dump editor 载入/校验/保存往返
10. comparator A/B 差异
11. dump history 列/重命名/删除
12. cancel-task（中途 kill）

输出：每项 `PASS`/`FAIL` + 汇总；非零退出码 = 失败。CI 必跑。

**实际实现（S0-S7 完成后落地）**
`crates/nfc-core/src/bin/selftest.rs`（14 项，全部 mock 驱动）：

| # | 用例 | 覆盖 |
|---|---|---|
| 1 | `case_connect_detect` | connect → detect → guidance（含 chunk 边界） |
| 2 | `case_read_ic_saves_dump` | read-IC → ETA 全链 → dump 自动保存 → TaskDone |
| 3 | `case_write_ic` | 确认写卡 + mfclassic 六参 |
| 4 | `case_format_card` | 格式化参数（源=目标=temp.mfd） |
| 5 | `case_write_uid_and_lock` | block0 读取 + 写/锁确认（含取消分支） |
| 6 | `case_hard_nested_manual` | 采集七参 + 手动状态机 |
| 7 | `case_hard_nested_autorun` | autoRun 递归至 unknown 空（带轮次上限防死循环） |
| 8 | `case_dict_test` | 选字典 + 四参 + 命中落盘 |
| 9 | `case_dump_roundtrip` | dump 往返 / 非 64 倍数拒 / 空拒 / trailer |
| 10 | `case_registry` | registry 往返 + UID 大小写折叠去重 |
| 11 | `case_uid_and_keys` | UID 解析 + save_keys 剔除默认密钥 |
| 12 | `case_cancel` | 中途 kill → 清 pending → signal |
| 13 | `case_format_duration` | 0 / 3599 / 3600 边界 |
| 14 | `check_exit_codes` | 退出码四分支 |
| 15 | `case_phone_wristband` | read-uid（样本 dump）→ write-uid（mock 成功）→ write-data（读回→改→写回全链） |

- 每项用 `catch_unwind` 独立捕获，单项失败不影响其余
- autoRun 用例带 `guard < 50` 轮次上限——状态机若有死循环，selftest 会
  **失败退出**而非挂死 CI
- ✅ **第 9-11 项（dump editor / comparator / history）已由 S10 的
  app 层 selftest 覆盖**（`c_dump_panels_render` / `c_editor_*` /
  `c_comparator_*` / `c_history_*`，见 §6 的 UI 用例与 §9 表）。本表
  保留数据层往返用例（`case_dump_roundtrip` / `case_registry`），
  面板交互的覆盖在 app 侧。
- ✅ 已实际运行，14/14 通过（`cargo run -p nfc-core --bin selftest`）

要点：
- **不需要 `libgtk-3-dev`**：`rfd` 用默认特性 `xdg-portal` + `wayland`，

- **不需要 `xvfb-run`**：`--selftest` 走 egui 的测试上下文

- **不构建 `framework/bin`**：C 工具是子模块，需 autoconf/libtool，

### 9.1 HardNested 的两处刻意偏离

1. **无进展即停**：原版 `command.js:341-350` 只要 `autoRun` 就**无条件**递归
   下一轮，若 `cropto1_bs` 始终找不出密钥会**无限递归**（原版靠进度条
   停在同一格来暴露问题）。我们加了显式终止条件：破解后 `unknown` 数量未减少
   即停（`HardNestedRunner::after_crack_guarded`）。
2. **空列表不崩**：原版 `command.js:352` 直接 `knownKeyInfo[0][0]`，
   列表为空会抛 TypeError 把整个窗口带崩。我们返回收工并记日志。

### 9.2 本表无法覆盖的验证

本表只能核到「派发了什么、参数对不对、确认闸在不在」。
`tools/verify_parity.py` 会在 CI/本地比对 `ALL_ACTIONS` 与本表是否一一对应，
新增或删改 action 而忘了改表会直接失败。**以下三类必须真机 / 真窗口人工验收**：

1. **系统弹窗实际弹出**——本机无图形界面，`rfd` 只验证到「能编译、队列可收发、流程顺序正确」。见 docs/02 §6.11③④。

2. **真实读卡器响应**——`nfc-mfdetect` / `nfc-mfclassic` / `nfc-mflock` 等均未在真机上跑过；`framework/bin` 不存在于本仓库。

3. **写卡不可逆**——`write-IC` / `format-card` / `lock-ufuid` 一旦执行即不可撤销。人工验收请先用可弃的测试卡，并确认 `temp.mfd` 备份闸生效（故意拔掉读卡器，确认程序中止而非继续格式化）。
