> 本次重定稿修正了旧版三处与上游不符的设计：

## 1. 背景与决策链

用户五步流程：

| # | 步骤 | 动作 | 归属 |
|---|---|---|---|
| ① | 先解好卡 | mfoc 全解母卡 → dump | **已有** `read-IC` |
| ② | 读取卡号 | 取母卡 block0（含 UID） | 新增 `phw-read-uid` |
| ③ | 写卡号到中介卡 | 写 UID 位 / 写数据扇区 | 新增 `phw-write-uid` / `phw-write-data` |
| ④ | 手机/手环模拟 A 卡 | 手机 app 侧 | 不涉及本程序 |
| ⑤ | 写手机/手环 | 写 UID 到手环卡 | 复用 `phw-write-uid`（nfc-mfsetuid） |

**已确认决策：**

| # | 决策 | 值 |
|---|---|---|
| 1 | 数据格式 | 母卡 **block0 完整 16 字节**（含 UID+BCC+SAK+厂商数据），大写 hex 32 字符 |
| 2 | 卡号来源 | **读当前卡**：`nfc-mfdetect -O<temp.mfd> -f<keys>`，读后取 temp 前 16B（对齐上游，不弹文件选择） |
| 3 | 数据扇区默认位置 | **扇区 0 块 1**（UI 可配置，**块限 1-2**：块 0 为只读 UID 块、块 3 为扇区尾块，均禁写） |
| 4 | 写数据扇区实现 | 读回 → 程序改块 → 整卡写回（`nfc-mfclassic w A u <temp> <temp> f`），**零新增底层** |
| 5 | 密钥 | 中介卡默认密钥 `ffffffffffff`（空白 CUID/UFUID），读回用现有 `keys.txt` |
| 6 | 写 UID 位 | `nfc-mfsetuid -q <block0hex>`；block0 BCC 不自洽时追加 `-f`（对齐上游 `block0_bcc_ok`） |
| 7 | 块号越界 | 直接报错不 spawn（`dialog_msg_phw_sector_block_invalid`），不在工具侧兜 |
| 8 | temp 文件 | **复用**现有 `temp.mfd`（不新增 `temp_phw_*.mfd` / `keys_default.mfd`）；失败即删 |

| `该扇区访问控制位损坏_写入将会损坏卡片_已重新设置` | 写前校验/修复访问控制位 |

## 3. 功能定义（4 个 action）

| action | 按钮 | 输入 | 动作 | 门禁 |
|---|---|---|---|---|
| `open-phw-window` | 主窗「写卡」列「手机/手环」入口 | — | 打开模态面板 | `connected=false, idle=false` |
| `phw-read-uid` | 读取卡号 | 无（读当前卡） | mfdetect 读回 → 取 block0 → 缓存 + `EventItem{Uid}` | `connected=true, idle=true` |
| `phw-write-uid` | 写入卡号 | 已缓存 block0 | 危险确认 → `nfc-mfsetuid -q <hex> [-f]` | `connected=true, idle=true` |
| `phw-write-data` | 写手机手环 | 已缓存 block0 + 目标块 | 危险确认 → 读回 → 改块 → 写回 | `connected=true, idle=true` |

> 说明：`phw-write-uid` 同时服务于步骤③（中介卡）与步骤⑤（手机/手环卡）—— 同一动作，目标卡不同。
> UI 用引导文案区分。门禁计数随之由 30→34 action、connected 10→13、idle 13→16、并集 14→17。

## 4. 数据流与命令契约

### 4.1 读卡号（phw-read-uid）

```
nfc-mfdetect -O<temp.mfd> -f<keys>      # 复用 detect::detect_args(paths, true)
→ 读 temp.mfd 前 16B → block0Hex（大写，32 字符）→ 缓存
→ 读后清理：temp.mfd 存在但 0 字节则删（复用 detect::purge_empty_temp）
```

- 失败分支：工具非零退出 / temp 不存在 / 长度 <16B → 报 `log_msg_card_read_failed`，不缓存。

### 4.2 写 UID 位（phw-write-uid）

```
nfc-mfsetuid -q <block0hex>            # BCC 自洽
nfc-mfsetuid -q <block0hex> -f         # BCC 不自洽时（对齐上游 force_bcc）
```

- `block0_bcc_ok(hex)` = `hex[0]^hex[1]^hex[2]^hex[3] == hex[4]`（对齐上游 `commands.rs:1033`）。
- 无缓存时不 spawn，报错 `dialog_msg_need_phw_read_uid_first`。

### 4.3 写数据扇区（phw-write-data）

```
校验: 扇区 0..=15 且 块 1..=2，否则报 dialog_msg_phw_sector_block_invalid 并直接返回
危险确认框（含 block0 hex 与 目标扇区/块号）
step1 读回:  nfc-mfdetect -O<temp.mfd> -f<keys>
step2 改块:  读 temp.mfd → 偏移 (sector*4+block)*16 处写入 block0 16B → 写回 temp.mfd
step3 写回:  nfc-mfclassic w A u <temp.mfd> <temp.mfd> f
收尾:        无论成败删除 temp.mfd
```

**命令设计依据（已读 `nfc-mfclassic.c` 源码确认）：**
- `A` = KeyA + **大写 = tolerate failures**（认证失败扇区跳过，不写坏非默认扇区）。
- `u` = 非指定 UID（下档 `U<uid>` 分支不触发）。
- 第 5 参 = keys.mfd；工具会比较其**前 4 字节 UID 与当前卡 UID**，不匹配且无 `f` 则中止。
  此处**用读回 dump 自身作 keys.mfd**：前 4 字节 = 中介卡 UID（匹配）+ 密钥区 = 读回实际密钥
  → 校验通过、认证正确（对齐上游，因此无需自造全默认密钥文件）。
- 整卡写回时，非默认密钥扇区认证失败被跳过 → **不破坏原数据**；目标扇区必须为默认密钥（空白卡前提）。

## 6. 门禁与异常路径

| 场景 | 行为 |
|---|---|
| 设备未连接 | 三个 phw 动作禁用（走 connected 门禁；nfc-list 例外规则不涉及本组） |
| 任务运行中 | Busy 门禁，禁止启动（含内部 mfdetect 复用） |
| 连接中 | 不禁止（`not_while_connecting=false`，仅 `conn-usb-devices` 例外） |
| 无缓存 block0 | 两个写动作报错 `dialog_msg_need_phw_read_uid_first`，不 spawn |
| 扇区 >15 或块 ∉ 1-2 | 报错 `dialog_msg_phw_sector_block_invalid`，不 spawn |
| block0 hex 长度 ≠ 32 | 报错，不缓存 / 不 spawn |
| temp.mfd 缺失或长度不足 | `log_msg_card_read_failed`，清理 temp |
| `nfc-mfsetuid` 非零退出 | `log_msg_write_failed`，device_state 不误标成功 |
| 写回失败 | 报错并删除 temp.mfd；提示目标扇区可能仍为旧数据 |
| 运行中拔设备 | R9：解析该判定串 → failed（**勿臆造**：串形以实测为准，见 docs/02 §6.4） |
| 危险操作取消 | 不 spawn 写工具 |

## 7. 测试计划

### 7.1 单元（nfc-core/src/tasks/phw.rs）
- `block0_bcc_ok`：自洽 / 不自洽各一例，含奇偶校验位全 0 与全 F 边界
- 扇区/块换算：`(0,1) → (0*4+1)*16 = 16`；`(15,2) → (15*4+2)*16 = 992`
- 块号校验：块 0 与块 3 均拒绝；扇区 16 拒绝

## 9. 风险与备用方案

| 风险 | 等级 | 缓解/备用 |
|---|---|---|
| 手机/手环芯片不支持 magic 写 UID（T9） | 高 | 真机验收前置；若不可行，步骤⑤降级为仅支持 CUID 类，UI 提示 |
| 整卡写回对 CUID 的 block0 行为未验证（读回原样写回，不应改 UID） | 中 | 真机 T8 确认；若 CUID 拒绝标准写 block0 → 备用**单块写**方案（保留不实施） |
| 中介卡非默认密钥（非空白卡） | 中 | UI 前置提示 + 危险确认；非默认扇区写回自动跳过不损坏 |
| 母卡未解/密钥不全导致读回扇区缺失 | 中 | `log_msg_card_read_failed` + 提示先 `read-IC` 解卡 |
| 上游后续再改 phw 契约 | 低 | 门禁 4 项对拍项钉住关键行为，漂移会显式变红 |

**排除的替代方案**：自造 `keys_default.mfd` 全默认密钥文件（旧版方案 §4.3，上游不需要，已删除）；
自制单块 C 工具（需 MSYS2 交叉构建，违背"不构建 C 工具"原则）。
