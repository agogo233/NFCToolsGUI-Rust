## 3. 39 个 action 规格（逐条）

> 前置条件标注：**连接**=需 `is_device_connected`；**空闲**=需 `!is_running_task`。
> 所有任务启动前置两门禁：未连接（除 nfc-list 例外）→ `NotConnected`；运行中 → `Busy`。

### 3.1 设备类

| action | 输入 | 调用/逻辑 | 解析与副作用 | 前置 |
|---|---|---|---|---|
| `scan-usb-devices` | 无 | `serialport::available_ports()` → 全 port 路径 | 与上次结果比对，变化才推 `Event::DeviceList` | 任意 |
| `conn-usb-devices` | device 路径 或 `" "` | `" "`→断开：state=None、connected=false；否则写 `libnfc.conf` 后 spawn `nfc-list` | 成功=`NFC device: NFC_Device opened`；失败=`Unable to open NFC device`；期间 state=Connecting(#b6b239) → Connected(#54ad6c)/Failed(#cf4152) | 连接中禁点 |

`libnfc.conf` 内容：
```
device.name = "NFC_Device"
device.connstring = "pn532_uart:{device}:{speed}"    // speed 默认 115200，可在设置面板选（19200/460800/921600 等）
```

> S18：`serial.rs::write_nfc_config(paths, device, speed)` 按 `state.current_speed` 写 `libnfc.conf`，
> 连接时由 `ConnectFlow::with_speed` 注入；速度切换在**下次连接**生效（设置面板有提示）。

### 3.3 写卡类

| action | 输入 | 调用/逻辑 | 解析与副作用 | 前置 |
|---|---|---|---|---|
| `write-IC` | dumpId（绝对路径 或 dumpfiles 下文件名） | `read_ic_then_exec(msg, status, isSaveDump=true, cmd, args)`：先 `nfc-mfdetect -O{temp.mfd} -f{keys.txt}`（备份）→ save_keys → 危险确认 → `nfc-mfclassic w A u {mfd} {temp.mfd} f` | 退出码 0→log_msg_write_success / 非0→write_failed；结束删 temp.mfd | 连接+空闲 |
| `format-card` | 无 | 同上但 `nfc-mfdetect -N`（检测）+ `nfc-mfclassic f A u {temp.mfd} {temp.mfd} f` | 结束删 temp.mfd | 连接+空闲 |
| `write-ufuid-uid` | 无 | rfd 选 dump(.dump/.mfd) → 读前 16 字节 → 大写 hex=block0 → 长度<32→`log_msg_dump_file_too_short` → 危险确认（含 block0 内容）→ `nfc-mfsetuid -q {block0}` | 读文件失败→read_dump_file_failed | 连接+空闲 |
| `lock-ufuid` | 无 | 危险确认（dialog_msg_card_will_be_locked）→ `nfc-mflock -q` | — | 连接+空闲 |

`read_ic_then_exec(msg, statusMsg, isSaveDumpFile, cmd, args[, finish])` 统一流程：
1. check_key_file()；重置 new_keys/known/unknown
2. `nfc-mfdetect`（isSaveDumpFile ? `-O temp -f keys` : `-N -f keys`）
3. finish：save_keys(new_keys)；isSaveDumpFile 且 temp.mfd 空 → 删空文件；isSaveDumpFile 且 temp 不存在 → log_msg_card_read_failed（**状态按 D5 用 error 语义**，不做成成功）
4. 第二步 exec；完成后 `fs::remove(temp.mfd)`

## 4. 解析规则（model/parse.rs，逐字移植）

### 4.1 mfoc 流程（tasks/mfoc.rs）

```
spawn mfoc [args..., -O temp.mfd, -f keys.txt]
逐行（stdout+stderr）：
  - parse_key_info(line) → 累计 known/unknown
  - 含 "UID (NFCID1):" → 取其下标 i+14 起 14 字符，去空白 → card_id
  - update_eta(line)：
      pending_line 累积；取最后一个 '\n' 前的完整行
      统计 /\[Key: /g 次数 → keys_done
      keys_total = 13(默认) + keys.txt 条数 + -k 参数条数
      节流 1000ms；ETA = (now-start)/done*(total-done) → format_duration
      done>=total → 100%
完成：
  1. save_keys(new_keys)
  2. temp.mfd 不存在或空 → 删空文件 + log_msg_dump_empty_not_saved
  3. 否则保存：rfd save，默认 dumpfiles/{card_id||"card"}_{yyyy_MM_dd_HH_mm_ss}.mfd
     - 用户取消 → 自动存 dumpfiles 默认名（log_msg_dump_auto_saved）
  4. Event::DumpSaved + Guidance{write-IC/open-dump-folder}
     - core 侧 DumpSaved 只落历史列表 + 一条 success 事件；
       引导条与**自动打开转储编辑器**由 app 侧在读盘续接完成后补上
       （见 §3.5 与 docs/02 §6.38）
```

`format_duration(sec)`：`3600+ → hh:mm:ss`；否则 `mm:ss`，各部分补零 2 位。

### 4.2 keyInfoStatistic（detect/mfoc 共用）

```rust
let re = Regex::new(r" (\w{5}|\w{7})\s+Key \w(: \w{12}|)").unwrap();
// 每条匹配 match_str；sector = i/2 （每扇区 KeyA/KeyB 两条匹配）
// match_str[1]=='F'（已知）→ key = match_str[16..28]（12 hex）；key_type = match_str[13]（A/B）
// match_str[1]=='U'（未知）→ 记录 (sector, key_type)
```

### 4.3 libnfc-collect / cropto1_bs / nfc-mfdict / nfc-list

```rust
// libnfc-collect
//   "Found tag with uid " → substring(i+19, i+27) = uid（8 字符）
//   "collecting nonces for key" → key_type=substring(i+26, i+27)；regex r"\(sector (\d{1,2})\)" → sector
//   进度 = total - remaining + 1 / total
// cropto1_bs / nfc-mfdict
//   "Key found:" → substring(i+11, i+23) = 12 hex → save_keys + 移除 unknown 匹配项
//   "Found Key: " → 同上
// nfc-list 连接判定
//   "NFC device: NFC_Device opened" → 成功
//   "Unable to open NFC device"     → 失败
//   （原版无第三判定串；运行中拔出不打印专用标记，
//     表现为工具非零退出 / stderr，见 S4 parse 的退出码分流）
```

### 4.4 输出行预处理

- 追加日志前剥离 `\33[2K` 前缀（即回退上一行再写新内容）。
- `\n` 剥离后按行推送事件；无 `\n` 的散行累积成行。

## 5. HardNested 状态机（tasks/hard_nested.rs）

### 5.1 状态

```
Idle ──── hard-nested-config-done(autoRun) ────▶ AutoDetecting
Idle ──── hard-nested-config-done(手动) ────────▶ Collecting
AutoDetecting ── nfc-mfdetect 完成 ──▶ Collecting
Collecting ── libnfc-collect 完成 ──▶ Cracking | SavingNonces(collectOnly)
SavingNonces ── 保存完成 ──▶ Idle
Cracking ── cropto1_bs 完成 ──▶ Idle（非 autoRun）| Collecting（autoRun 递归下一条）
任意状态 ── cancel ──▶ Idle
```

### 5.2 run-hard-nested 步骤

```
1. known_block = (known_sector+1)*4-1；target_block = (target_sector+1)*4-1（扇区→trailer 块）
2. unknown 为空 → 提示 log_msg_tried_decrypt_all_unknown_keys，结束
3. spawn libnfc-collect [knownKey, known_block, knownKeyType, target_block, targetKeyType, "bin", nonces_file]
   → 逐行 §3.3 → 进度推送
4. 完成：
   - collectOnly：
        nonces.bin 非空 → rfd save 默认 {uid}_{target_block}{targetKeyType}.bin → fs::rename
        nonces.bin 空   → log_msg_not_saved
   - 否则 spawn cropto1_bs [nonces_file]
        → 逐行 §3.3 → 完成后：autoRun → 递归 run-hard-nested(下一条 unknown)；否则结束
5. 全程可取消
```

## 9. dump 数据模型（model/dump.rs）

```
Sector { lines: [String; 4] }            // 每行 32 hex
Dump { path, bytes: Vec<u8>(1024), sectors: Vec<Sector>(64) }
Dump::from_bytes(&[u8]) -> Option<Dump>          // 长度须 1024
Dump::to_hex_lines() -> Vec<String>              // 每 32 字符一行
Dump::from_hex_lines(&[String]) -> Option<Dump>  // 保存时校验
Dump::validate(lines) -> bool                    // 每行恰 32 且（保存时）hex
```

hex 编辑器校验（对齐原 checkData）：每组 4 行；每行长度 32；保存时校验 hex 字符集；非法行红框（#e96666 + 阴影），合法 #ccc。
着色：block0 首行整行 `.uid`；每个扇区第 4 行（trailer）切 `[0,12)keyA / [12,18)access / [18,20)无着色 / [20,32)keyB`。
「更新颜色」按钮走**不校验 hex 字符集**路径（对齐原版 checkData(false)）。

## 10. dump 比较器（对齐原 markDifferentStrings）

- 逐字符 diff：`dumpA[i][j][k] != dumpB[i][j][k]` → 该位高亮（mark-bg）；整行有差异才包裹。
- 扇区数不等（修正 D3）：多出扇区整段高亮、对侧留空行。
- UI：每扇区标签「扇区 N」+ 4 组 `A: …` / `B: …` / `<hr>`。
