- ⚠️ 本步**未跑 `cargo test`**（AGENTS.md 规则 8 禁用编译）。替代校验：`rustfmt` 语法解析
  + `/tmp/opencode/verify_s3.py` 78 项静态校验（原文对齐 / fixture / i18n / 文档一致性 / 泛型声明）。
  编译与测试需接入 CI 后补跑；上面「验证」小节的 `cargo test` 绿属待办。

**偏离原版**
1. `setting-nfc-config` 与 `update-device-status` 两个 IPC 在 renderer 里做的事几乎相同
   （同色、同 `isConnectingDevice` 开关），合并为一个 `Event::DeviceState`，少一条消息。
2. `judge_connect` 判定**累计**输出而非单个 data 块：原版按块 `indexOf`，标记被拆到两块时漏判。
3. `finish` 未命中任何标记时返回 `Some(false)` → `DeviceState::Failed`；原版此时 `isDeviceConnected`
   沿用上一轮的值（首次连接为 false，结果一致；重连失败后会残留上一次的成功态，属原版缺陷）。
4. 写 `libnfc.conf` 失败或 `nfc-list` 启动失败时主动置 `DeviceState::Failed`；
   原版 `throw err` 后无任何反馈，`isDeviceConnected` 保持 Connecting 中间态。
5. 累计判定标记串冲突时以 `NFC device: NFC_Device opened` 优先（原版为后写的
   `Unable to open` 覆盖，实际输出不会同现两条，仅测试显式覆盖）。

**回滚**：revert S3

## S11 收尾对齐（功能 parity）

**状态：全部完成（第一步 Engine 编排 / 第二步 系统文件对话框 + 接线 / 第三步 parity 表）**

### 第一步：Engine 编排层（已完成）

S0–S10 里 `AppState` 每个字段都有归属，但**没有任何一处真正 spawn 过进程**——
UI 产出的 `Action` 进队列就被 `clear()` 丢弃。本步补上这一层。

- core 新增 `engine` 模块：`Engine::dispatch`（动作 → 工具 + 参数）与
  `Engine::pump`（输出回流 + 退出收尾）
- `Action` 从 app 迁到 `core::engine`（不含 GUI 类型，且是 `ACTION_SPECS`
  那 30 个 action 名的运行时载体，放 core 才能让 Engine 直接消费）
- app 侧 `pending.clear()` 换成 `consume_pending()`：用 `mem::take` 而非
  `drain`，避免把 dispatch 期间新入队的动作一起丢掉
- `main.rs` 接上 `Engine::with_real_tools`，`framework/bin` 定位规则复用
  `runner::framework_bin`（打包时 = exe 旁，开发时 = 仓库根下）
- `ToolRunner` 加 `started_last()`（带默认实现），使 `Box<dyn ToolRunner>`
  也能被断言"到底跑了什么命令、什么参数"

### 第二步：系统文件对话框 + 写卡/文件类接线（已完成）

**新增依赖**：`nfc-app` 引入 `rfd`（默认特性 `xdg-portal` + `wayland`，
`gtk3` 可选且非默认 → 不引入 GTK 系统依赖）。core **未新增任何依赖**。

**两个新模块**

- `app/dialogs_host.rs`：`nfc-dialog` 专用工作线程 + 通道。rfd 的
  `pick_file()` / `save_file()` 阻塞，故不能上 UI 线程。退出时不 join。
- `app/dialogs_ui.rs`：应用内危险确认模态窗（不用系统原生框，原因见
  docs/02 §6.11①）。

**关键设计：core 一行未改**

`prepare_write(paths, dump_id, dialog)` 与
`prepare_write_uid(..., dump_path)` 本就接受**预选好的路径**。故流程拆两段：
app 弹系统框选文件 → 路径作载荷传入 → engine 走 `Some` 分支不弹框。
测试仍可用 `ScriptedDialog` 完整驱动。`MockDialog` 正名为
`ScriptedDialog`（它已进入生产路径，叫 Mock 会误导），保留
`pub type MockDialog = ScriptedDialog` 别名，测试代码零改动。

**已接线的 action（本步新增）**

- 文件类：`save-log`、`open-dict-file`、`open-dump-folder`、`open-history-keys`、
