# ISO/IEC 14443 协议层与卡片激活

> 依据：ISO/IEC 14443-1/-2/-3/-4（物理特性 / RF 信号 / 初始化与防碰撞 / 传输协议），
> NXP `AN10833`《MIFARE type identification procedure》Rev. 3.9（2025-12-15）。
> 本文件描述**所有 MIFARE 卡共用的 Type A 激活与识别协议**，是
> `nfc-mfdetect` 类型识别、`mfoc` 读卡、以及 UID 处理的第一性原理。

---

## 1. 分层结构（ISO/IEC 14443）

ISO/IEC 14443 由 4 部分组成：

| Part | 名称 | 内容 |
|---|---|---|
| Part 1 | Physical characteristics | PICC 的物理尺寸、天线 |
| Part 2 | RF signal and power interface | 载波 13.56 MHz、调制与编码、场强上下限；分为 **Type A**（= MIFARE）与 **Type B** |
| Part 3 | Initialization and anticollision | 通信启动与 PICC 选择（Card Activation Sequence）；分 Type A / Type B |
| Part 4 | Transmission protocol | PCD 与 PICC 间数据交换协议（**T=CL**） |

- **Type A**：MIFARE 全家族、NTAG、DESFire、Plus 均属此型。本项目所有卡交互均为 Type A。
- **Type B**：少数银行/身份证卡使用，本项目不涉及。

### 1.1 MIFARE 协议族与 ISO 14443 的关系

- **原生命令集（native command set）**：基于 ISO/IEC 14443-3 的私有命令
  （MIFARE Read/Write/Auth 等），不依赖 T=CL。适用于：
  MIFARE Classic 1K/4K、MIFARE Ultralight (EV1/C)、MIFARE Plus (SL1/SL2)。
- **T=CL 协议**：ISO/IEC 14443-4 定义。适用于：MIFARE DESFire 家族、MIFARE Plus (SL3)、
  NXP 双/三接口卡（SmartMX）。
- **Crypto1**：MIFARE Classic 1K/4K 专用的私有流密码，见 [02-Crypto1.md](02-Crypto1.md)。

## 2. 载波、调制与编码（Part 2, Type A）

| 参数 | Type A 取值 |
|---|---|
| 载波频率 | 13.56 MHz（`fc`） |
| 数据速率（PCD→PICC） | 106 kbit/s |
| PCD→PICC 调制 | ASK 100%（OOK） |
| PICC→PCD 副载波 | 848 kHz（`fs = fc/16`），Manchester 编码，负载调制 |
| 数据速率（PICC→PCD） | 106 kbit/s |
| 帧格式 | 起始位 + 数据字节（LSB 先）+ 奇偶校验位 + 结束位 |

> 本项目 PN532 通过 13.56 MHz 天线与卡通信，PN532 内部完成 ISO 14443-2 的调制/解调，
> 上层（libnfc / 本项目 Rust）只关心字节流与命令码，故本层对源码透明。

## 3. 卡片激活序列（Card Activation Sequence, Part 3）

### 3.1 状态机

PICC 从 `IDLE` 到 `ACTIVE` 经过以下状态（简化）：

```
        REQA(26h)/WUPA(52h)            防碰撞(SEL)               Select
IDLE ────────────────────▶ READY ────────────────▶ READY* ────────▶ ACTIVE
     (ATQA 应答)          (UID 逐位解析)          (SAK 应答)
```

### 3.2 请求（REQA / WUPA）

| 命令 | 代码 | 用途 |
|---|---|---|
| REQA | `26h`（7 位） | 请求应答，只唤醒 IDLE 状态卡 |
| WUPA | `52h`（7 位） | 唤醒所有状态（IDLE + HALT）卡 |

### 3.3 防碰撞（Anticollision）

- 使用 **SEL（Select）命令** 分 **级联级别（Cascade Level, CL）** 逐级解析 UID。
- 单尺寸 UID（4 字节，如 MIFARE Classic 1K 4-byte NUID）：1 级防碰撞即完成。
- 双尺寸 UID（7 字节，如 MIFARE Classic 1K 7-byte UID、NTAG、Ultralight）：
  需要 CL1 + CL2 两级。

| 命令 | 代码 | 说明 |
|---|---|---|
| Anticollision CL1 | `93h 20h` | 级联级 1 防碰撞 |
| Select CL1 | `93h 70h` | 级联级 1 选择 |
| Anticollision CL2 | `95h 20h` | 级联级 2 防碰撞 |
| Select CL2 | `95h 70h` | 级联级 2 选择 |

**级联标记（CT, Cascade Tag）**：`88h`。当 UID 尚未完整接收时，PICC 在 UID 第 1 字节返回 `88h`，
提示还需下一级防碰撞。

### 3.4 ATQA（Answer To Request, Type A）

PICC 对 REQA/WUPA 的应答，2 字节。**位编号从 LSBit = bit 1 开始（不是 bit 0）**，
且 **LSByte 先传输**（故手册中的 `0x0044` 实际线序收为 `44 00`）。

| 位 | 含义 |
|---|---|
| bit 1-5 | 帧防碰撞支持（bit 1 = 1 表示支持） |
| bit 6-7 | RFU |
| bit 8-9 | **UID 尺寸**（AN10833 Table 2）：`bit8=0,bit9=0` 单尺寸(4B)；`bit8=1,bit9=0` 双尺寸(7B)；`bit8=0,bit9=1` 三尺寸(10B) |
| bit 10-15 | RFU / 厂商自定义 |
| bit 16 | RFU |

> **重要**：NXP 明确建议**不要用 ATQA 识别芯片或提取 UID 尺寸**——ATQA 可能被碰撞、可能
> 误导（见 AN10833 §2.3）。应使用 GetVersion（若支持）或 SAK。本项目的 `detect.rs`
> 也是以 SAK 为主判定卡型。

### 3.5 SAK（Select Acknowledge）

PICC 对 SEL 的应答，1 字节。**只有最后一级级联（UID 完整时）的 SAK 才用于芯片类型判定。**

| 位 | 含义（AN10833 §2.4） |
|---|---|
| bit 2 | `1` = UID 未完成（级联，需下一级） |
| bit 3 | `0` = UID 完成（bit 2=0 时） |
| bit 4 | MIFARE Classic 家族标记（1K SAK=0x08 置位） |
| bit 5 | `1` = PICC 兼容 ISO/IEC 14443-4；**例外**：MIFARE Classic 4K 的 SAK=0x18 也置位，作 4K 内存标记 |
| bit 6 | `1` = PICC 兼容 ISO/IEC 18092（NFC） |

> SAK 是**位映射**，应按位判断 MIFARE 类型，**不要用 SAK 的完整字节值**判定
> （AN10833 §2.4.1）。例如 Classic 1K 的 SAK=0x08（bit 4），Classic 4K 的 SAK=0x18
> （bit 4 + bit 5），两者共享 bit 4；bit 5 置位 → 4K。

## 4. 关键卡型的 ATQA / SAK / GetVersion 对照（AN10833 汇总）

### 4.1 不支持 GetVersion 的卡（用 ATQA/SAK 判定）

| 卡型 | ATQA | SAK | 说明 |
|---|---|---|---|
| MIFARE Classic EV1 1K | `00 x4`（x=bit7） | `08h` | 7B UID 时 bit7=1 → `0x44`；4B NUID → `0x04` |
| MIFARE Classic EV1 4K | `00 x2`（x=bit7） | `18h` | 同上：7B UID → `0x42`；4B NUID → `0x02` |
| MIFARE Ultralight | `00 44h` | `00h` | 全 Ultralight 家族共用 ATQA/SAK |
| MIFARE Ultralight C | `00 44h` | `00h` | 与 Ultralight 相同 ATQA/SAK，需读 block0 区分 |
| MIFARE Plus 2K/SE(1K) | `00 04h`（4B NUID）/ `00 44h`（7B UID） | `08h` | SL1 |
| MIFARE Plus 4K | `00 02h`（4B）/ `00 42h`（7B） | `18h` | SL1 |

> 具体对照见 [01-MIFARE-Classic.md](01-MIFARE-Classic.md) 与
> [03-Ultralight-NTAG.md](03-Ultralight-NTAG.md)。

### 4.2 支持 GetVersion 的卡（NXP 推荐方式）

**GetVersion 命令**用于精确识别芯片。响应第 2 字节（HW/Product Type）的低半字节给出
**MIFARE 产品族**，高半字节定义设备类型：

| 第 2 字节低半字节 | 产品 |
|---|---|
| `0xX1` | MIFARE DESFire & MIFARE DUOX |
| `0xX2` | MIFARE Plus |
| `0xX3` | MIFARE Ultralight |
| `0xX4` | NTAG |
| `0xX7` | NTAG I²C |
| `0xX8` | MIFARE DESFire Light |

高半字节：`0x0`=原生 MIFARE IC，`0x8`=实现，`0x9`=Java Card applet，`0xA`=MIFARE 2GO。

> 本项目的 `nfc-mfdetect` 走 libnfc 的经典激活序列（ATQA/SAK），不使用 GetVersion，
> 因其面向 MIFARE Classic 系列（不支持 GetVersion）。

## 5. UID / NFCID1 结构

### 5.1 UID 组成

UID 按 ISO/IEC 14443-3 分尺寸：

| 尺寸 | 字节数 | 说明 |
|---|---|---|
| 单尺寸（single） | 4 字节 | 如 MIFARE Classic 4B NUID、NTAG 的 4B 模式 |
| 双尺寸（double） | 7 字节 | 如 MIFARE Classic 7B UID、NTAG/Ultralight 7B |
| 三尺寸（triple） | 10 字节 | 少见 |

**双尺寸 UID 结构**（第 1 字节为厂商码）：

```
字节:   0      1      2      3      |  4      5      6
      SN0    SN1    SN2    BCC0   | SN3    SN4    SN5    SN6   BCC1
      └──────── 第1级 ────────┘      └───── 第2级 ───────┘
```

- `SN0`：厂商 ID（NXP = `04h`，ISO/IEC 7816-6 AMD.1）。
- **BCC0 = CT ⊕ SN0 ⊕ SN1 ⊕ SN2**（CT = `88h` 级联标记）。
- **BCC1 = SN3 ⊕ SN4 ⊕ SN5 ⊕ SN6**（异或校验，无 CT）。

### 5.2 单尺寸 UID（4 字节）

无级联，直接：

```
字节:   0      1      2      3
      SN0    SN1    SN2    SN3   (BCC0 仅在双尺寸时存在于 UID 内)
```

> 本项目 `crates/nfc-core/src/model/hex.rs` 与 `engine.rs` 的
> `uid_to_block0` / `block0_bcc_ok` 即按上述 BCC 规则实现，用于 Gen1a/Gen2 卡 UID 写入，
> 详见 [04-UID与Gen卡.md](04-UID与Gen卡.md)。
